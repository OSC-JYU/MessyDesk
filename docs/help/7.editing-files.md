# Correcting outputs

Let's take an example: You detected text from images and the result is almost right. Then it is sensible to fix that error.
But if you modify the result of optical character recognition, then we do not know anymore what was the machine product and what was corrected.

Solution: make a new version.

MessyDesk does not edit files in place without provenance. Instead, create a corrected version so it stays clear what was machine output and what was user-corrected.

The corrected version becomes the current version used in further processing. You can revert back to the original; because current versioning is single-step, that edited version is then permanently lost.

Current behavior:

- Text-like files (`text`, `html`, `json`, `csv`, and `*.json`) can be edited from the UI and saved as an edited version.
- Image files can be rotated in the UI and saved as an edited version.
- Save writes the current file to `<path>.original` (single backup slot) and replaces the current file content.
- Revert restores `<path>.original` and clears edited metadata.
- Text payloads are size-limited by `MAX_VERSION_TEXT_BYTES` (default 10 MB).

Note: only one backup version is kept (`.original`). A new save overwrites the previous backup.
