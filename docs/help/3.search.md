# Search

Search is a core functionality for exploring text-based research material within your project graph.

![search](search_index.jpg)

By connecting a **Search index** cruncher to your text files, you add those texts to a shared search index. Once indexed, you can run queries across the entire dataset.

> ⚠️ **Note:** No data is indexed by default. 

When you delete a Search cruncher, all associated text files are automatically removed from the search index. This graph-based approach keeps the indexing process transparent and gives you total control over your data.

## Why this approach?

*   **Version Control:** When running different text-processing experiments, you often generate multiple iterations of the same source text. This approach ensures your search results aren't cluttered with unwanted text variants.
*   **Granular Pipeline Indexing:** You can decide exactly *what* stage of your pipeline gets indexed. For example, you might generate a lemmatized token list from your corpus and choose to index only that list, while still using the search results to navigate back to the original source texts.
*   **Performance Optimization:** Digital humanities workflows can produce massive search indexes, especially when using intensive $n$-gram-based indexing to maximize discovery. By opting into indexing rather than automating it, you can utilize precise $n$-gram settings without bloating your storage with unused index data.

## Re-indexing

Occasionally, a search index can become corrupted or out of sync (for instance, due to interrupted processing or failed update requests). To resolve this, the platform provides a project-wide utility to completely rebuild your search index data from scratch.
