# ZIP File Handling

MessyDesk handles ZIP archives differently than typical file managers. When you import a `.zip` file into your project graph, its contents are not extracted automatically. To access the files inside, you must explicitly connect an **Unzip** cruncher to the archive node.

![Visual representation of a ZIP file branching into two separate Unzip crunchers based on file type](unzip.jpg)

## Why this step? Why not extract automatically?

ZIP archives—especially historical or legacy research datasets—often contain a messy mix of different file formats. Because MessyDesk workflows are heavily type-dependent, it is usually inefficient to dump everything into a single folder. 

The **Unzip** cruncher acts as a filter, allowing you to extract files selectively by type. As shown in the graph above, this approach offers several advantages:

* **Automated Sorting:** You can route images (e.g., JPEGs) to one processing pipeline and documents (e.g., PDFs) to another, straight out of the same archive.
* **Storage & Resource Efficiency:** If you only need the text documents from a massive multi-gigabyte archive that also contains video or audio files, you can choose to extract only the PDFs, saving valuable disk space and processing time.
* **No Pre-Sorting Required:** You don't have to manually clean, organize, or split your ZIP files on your local operating system before bringing them into your workspace.
